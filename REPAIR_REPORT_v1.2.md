# Model v1.2.1 computational repair report


Version note: Model v1.2.1 retains the corrected v1.2.0 core equations and non-recovery headline results, while adding the corrected recovery release protocol and later forensic-audit hardening. Historical references below to v1.2 describe that earlier repair stage rather than a different current model.
Date: 2026-08-27

This repair changes computational correctness and reproducibility only. It does not add wet-lab implementation instructions or retune parameters to obtain a favorable result.

## Correctness fixes

1. Corrected receptor two-compartment steady-state initialization and derived synthesis.
2. Recovery now targets the specified suppressed receptor instead of accepting either receptor.
3. Replaced the duplicated PRCC implementations with one mathematically correct shared implementation that controls only for sampled parameters.
4. Run-3 LHS and standalone sensitivity runs now use matched controls for each sampled parameter vector; Run 3 uses the X4 control.
5. Moved positivity failure checks out of intermediate solver RHS evaluations and into post-integration trajectory validation, while clipping only tiny numerical excursions.
6. Constitutive CCR5 comparator now clamps the actual stored surface/internal state from initialization onward.
7. Run-5 suppression-share plotting uses the same nonnegative numerator clipping as the registered metric.
8. `step_off()` now respects both `t_on` and `t_off`.
9. Unknown parameter overrides fail closed instead of silently creating unused keys.

## Reproducibility fixes

- Campaign LHS bounds are loaded from `parameters/sensitivity_ranges_v1.csv` rather than duplicated in Python.
- PRCC/LHS utilities are centralized in `src/stats_utils.py`.
- Run-8 stochastic forcing uses a stable child seed derived from the registered master seed.
- YAML run-intent files are checked against executable scenario defaults by regression tests.
- Model/documentation metadata updated to v1.2 and the state count corrected to 20 total states.
- Documentation references to nonexistent figure/solver-test files were corrected.
- Git lookup no longer emits stderr noise in release ZIPs without `.git` metadata.

## Verification

- `pytest -q`: 22 tests passed after the recovery-protocol correction.
- The full v1.2.0 campaign completed successfully after the prior repair; v1.2.1 changes only the dedicated recovery scenario and its figure/summary. The unchanged N=128 sensitivity outputs are retained.
- The corrected baseline receptor-only check remains exactly at normalized surface receptor abundance 1.0 for both receptor pools.
- The constitutive comparator stores normalized R5 surface abundance at 0.05 throughout the trajectory.
- The v1.2.1 recovery analysis is a clean two-phase release test: day-14 release removes scripted forcing and active infection-source states while preserving receptor, A/B/C, and Q-chain states. R5 reaches 90% of baseline approximately 5.85 days after release.

## Interpretation note

Because the baseline receptor equations were corrected, figures and summary values generated by v1.1 should be regenerated before being used in a manuscript. The v1.2 campaign deliberately retains unfavorable outcomes rather than retuning the model to rescue them.

## v1.2.1 recovery-protocol correction

The earlier recovery scenario removed scripted P5 forcing but left live infection in place, so infection-derived B could persist/rebound as CCR5 recovered. That test therefore mixed reversibility with continuing infection. v1.2.1 explicitly removes the upstream infection source at the release event while retaining stored circuit state. See `RECOVERY_PROTOCOL_CORRECTION_v1.2.1.md`.
